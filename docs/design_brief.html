Engineering Design Brief

Low-Power ESP32-C3 Smart Scale Main Board

This project is a compact, battery-backed smart-scale PCB built around the ESP32-C3-MINI-1U with external antenna support, a dedicated HX711 load-cell ADC, USB-C charging for a 1S 3000 mAh LiPo, and explicit low-sleep-current design choices. The cheapest sensible product architecture is a battery-always-present system using a linear charger, a low-IQ 3.0 V rail, a switched battery divider, and direct USB Serial/JTAG routing into the ESP32-C3 so there is no USB-UART bridge tax.

Design Options

Recommended
Option A

LDO-Based Battery-Backed Product Board

Use the battery as the always-present energy source, charge it from USB-C with MCP73831, regulate the system with a low-IQ TLV75530, and measure the bridge with HX711. Route USB D+/D- straight into the ESP32-C3 USB Serial/JTAG pins.

Pros
Lowest BOM cost while staying product-grade
No USB-UART bridge or power-path PMIC overhead
Simple firmware and assembly flow
Cons
Not optimized for battery-less USB operation
Active efficiency lower than a switching rail
Charge/load interaction must be budgeted
Verdict: best fit for “cheapest sensible architecture” and a battery-backed scale product.
Option B

Buck-Regulated Battery System

Keep the same charger and metrology path, but replace the LDO with a low-IQ switching regulator. This improves active efficiency and thermal margin during Wi-Fi bursts.

Pros
Better energy use during radio activity
Lower thermal stress at higher average load
More headroom if the feature set grows
Cons
Higher BOM cost
More EMI and layout discipline required
Solves a problem the present use case may not have
Verdict: technically cleaner for efficiency, but not the cheapest sensible first product architecture.
Option C

Premium Metrology + Power-Path Platform

Use a higher-spec ADC and a charger with full power-path behavior so the board behaves more like a mains-attached product while charging and running.

Pros
Best behavior with low battery during USB attach
More precision and firmware control headroom
Easier to scale into a more premium product tier
Cons
Breaks the low-cost target
Longer layout and bring-up cycle
Unnecessary complexity for the current brief
Verdict: reserve for a later revision if battery-less USB behavior or higher precision becomes mandatory.
Chosen Direction
Option A is the recommended baseline because the product is fundamentally battery-backed, the `ESP32-C3-MINI-1U` allows cheap direct USB programming, and the scale’s mostly-sleeping duty cycle does not justify a costlier switching power tree in the first revision.

Wiring & Assembly

Fig 4. Enclosure-level wiring concept showing the main PCB, LiPo pack, and load-cell harness.
01
Receive and inspect PCBs

Confirm board revision, USB-C connector footprint quality, module-pad finish, and antenna-edge keepout cleanliness before assembly.

02
Populate core power path

Verify `MCP73831`, `TLV75530`, CC resistors, bulk caps, and battery connector orientation before the ESP32 module is powered for the first time.

03
Mount MCU and analog front end

Assemble `ESP32-C3-MINI-1U`, `HX711`, and the related passives. Keep the analog zone clean and inspect for solder bridges around the HX711 inputs.

04
Install harness connectors

Attach the LiPo connector, load-cell connector, and any optional external-antenna pigtail or mating connector specified by the mechanical design.

05
Factory program and calibrate

Use USB Serial/JTAG through USB-C first; fall back to the factory pads if needed. Flash test firmware, read bridge counts, and apply a known-mass calibration.

06
Function test and sleep-current check

Verify charging, battery ADC, radio bring-up, load-cell stability, and the final deep-sleep current target with the bridge and divider disabled.

Serviceability
Keep the factory pads accessible even after enclosure integration. This board should be recoverable without desoldering the battery or opening the RF path.

Scale-Up Notes

  • If the product must charge and run gracefully with a deeply depleted or missing battery, move to a real power-path charger in the next revision.
  • If RF performance becomes enclosure-limited, reserve a future spin for antenna matching and feed optimization with the final mechanical stack.
  • If sleep-current margin is not met, add explicit bridge-power gating instead of changing the whole analog architecture.
